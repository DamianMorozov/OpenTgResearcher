## Сборка решения

Для сборки всех проектов требуется SDK .NET 10 или новее.

Проверка целевых платформ проектов, профилей публикации, CI и Docker, относительных ссылок тестовых проектов и отсутствия привязки тестов к локальным дискам, затем сборка решения:

```powershell
./Tests/SelfTests/Test-Net10.ps1
./Tests/SelfTests/Test-RelativePaths.ps1
dotnet restore OpenTgResearcher.slnx -p:Platform=x64
dotnet build OpenTgResearcher.slnx --no-restore -c Debug -p:Platform=x64 -p:AppxPackageSigningEnabled=false
```

### Тесты хранилища

`TgStorageTests` использует отдельную SQLite в памяти для каждого набора тестов, применяет настоящие миграции и заполняет таблицу версий. Соединение и контейнер зависимостей освобождаются после набора; пользовательская БД не требуется. Регрессионные тесты проверяют запись и чтение, изоляцию данных и освобождение ресурсов.

```powershell
dotnet test Tests/TgStorageTests/TgStorageTests.csproj -c Debug -p:Platform=x64
```

### Тесты бизнес-логики

`TgBusinessLogicTests` запускается через NUnit и VSTest, как тесты хранилища. Используется общее тестовое окружение с мигрированной SQLite в памяти. Проверяются доступ к данным через бизнес-логику, события настоящего мониторинга ресурсов, остановка событий, независимые экземпляры сервиса и сохранность общего кеша после освобождения мониторинга. Telegram и пользовательская БД не используются.

```powershell
dotnet test Tests/TgBusinessLogicTests/TgBusinessLogicTests.csproj -c Debug -p:Platform=x64
```

## Проверка страницы оборудования Desktop

Селфтесты проверяют исходную модель страницы: начальный обзор, минутную историю, пропуски и недоступные показания, паузу и продолжение, сохранность измерений при смене представления. Дополнительно проверяются привязки разметки, начальное состояние меню и русские и английские ресурсы.

```powershell
dotnet run --project Tests/SelfTests/Hardware/Hardware.SelfTest.csproj -c Debug -p:Platform=x64
dotnet test Tests/TgBusinessLogicTests/TgBusinessLogicTests.csproj -c Debug -p:Platform=x64
```

Для проверки настоящего окна закройте Desktop и укажите путь к опубликованному unpackaged-приложению. Пример публикации и двух вариантов запуска:

```powershell
dotnet publish Presentation/OpenTgResearcherDesktop/OpenTgResearcherDesktop.csproj -c Release -r win-x64 --self-contained true -o Tests/SelfTests/bin/HardwareApp -p:Platform=x64 -p:WindowsPackageType=None -p:WindowsAppSDKSelfContained=true -p:AppxPackageSigningEnabled=false
./Tests/SelfTests/Test-DesktopHardware.ps1 -ExecutablePath Tests/SelfTests/bin/HardwareApp/OpenTgResearcherDesktop.exe -Language Russian -Theme Dark
./Tests/SelfTests/Test-DesktopHardware.ps1 -ExecutablePath Tests/SelfTests/bin/HardwareApp/OpenTgResearcherDesktop.exe -Language English -Theme Light
```

Проверка создаёт отдельные настройки и БД, получает настоящие измерения, проверяет стартовый обзор, переключение графиков, паузу и продолжение, сохранение состояния кнопки глаза при навигации, доступность управления при ширине 800 и штатное закрытие без исключений. По пикселям настоящего кадра проверяются единый фон меню и страницы и контраст подписи шкалы графика. Снимки окна 1200×1000 и 800×900 и журнал сохраняются в `Tests/SelfTests/bin/HardwarePage/<идентификатор>/`. Подключение к Telegram не выполняется; установку и обновление через Velopack эта проверка не охватывает.

## Проверка сетевой активности Desktop

Страница «Сетевая активность» показывает операции текущего запуска: подключение и отключение Telegram, парсинг, скачивание файлов, проверку прокси и обновлений. Общая служба сохраняет активные операции и последние сто завершений; очистка истории не отменяет выполняющиеся действия. Состояние «Завершено» означает окончание действия, а состояние подключения Telegram отображается отдельно.

Строка парсинга содержит «Чтение ID X из Y»: X — начальный ID текущей запрашиваемой порции, Y — последний ID чата, а не количество существующих сообщений. ID публикуется до ожидания ответа; процент продвижения обновляется отдельно после чтения порции. При неизвестной верхней границе показывается только текущий ID. Проверки `NetworkParsingMessageIds` и `ParsingRequestIdsBeforeResponse` проверяют исходную модель страницы и настоящий обработчик порций с ответом из тестового кеша без подключения к Telegram.

При парсинге отображаются название чата и продвижение по сообщениям. Каждая загрузка файла показывает имя, переданный объём и процент скачивания по обратному вызову WTelegram. Строка операции компактная, без переносов; длинные названия сокращаются и доступны в подсказке. Процент обработки сообщений и процент скачивания файла различаются по типу операции и полной подсказке. Названия чатов и файлов подчиняются общему переключателю конфиденциальных данных; полные локальные пути в историю не записываются.

Блок «Активность» объединяет все операции: выполняющиеся, завершённые, отменённые и с ошибками. Парсинг и скачивание документов, фотографий и обложек сгруппированы по ID чата, поэтому одинаковые названия разных чатов не смешиваются. Нажатие заголовка раскрывает все действия чата из текущей истории. Отмена сохраняется в той же группе вместе с достигнутым прогрессом; названия подчиняются переключателю конфиденциальных данных. Раскрытие сохраняется при обновлении прогресса, смене языка и завершении загрузок. Действия без привязки к чату находятся в группе «Общие операции». Кнопка «Очистить историю» в заголовке блока удаляет только завершённые действия, включая отмену и ошибки; выполняющиеся операции сохраняются, а пустые группы исчезают. Сервис хранит последние 100 завершённых действий текущего запуска. Отдельного блока «Последние операции» нет.

Кнопка «Прервать парсинг» запрашивает подтверждение, отменяет собственный токен парсинга и показывает ожидание завершения. «Пауза» приостанавливает обработку следующих сообщений и запуск файлов, меняется на «Продолжить» и сохраняет текущий прогресс. Уже начатые запросы и передачи могут завершиться до ожидания на ближайшей границе обработки. Остановка работает и во время паузы. Проверка прокси и обновление программы продолжаются независимо. Ошибки отображения прогресса в синхронном и асинхронном обратных вызовах записываются в журнал; штатная отмена передачи не подавляется.

Автономные проверки запускают параллельные действия, ошибки и отмену, проверяют ограничение истории, ожидание паузы, продолжение и остановку с настоящим сервисом состояния загрузок. Проверяются отказ и ожидание ответа в диалоге прерывания, локализация кнопки продолжения и обработка исключений прогресса с записью в журнал. Проверки исходной модели страницы входят также в набор обновлений:

```powershell
dotnet run --project Tests/SelfTests/Network/Network.SelfTest.csproj -c Debug -p:Platform=x64
dotnet run --project Tests/SelfTests/Updates/Updates.SelfTest.csproj -c Debug -p:Platform=x64
```

Для проверки настоящего окна закройте Desktop. Скрипт использует отдельные настройки и БД; подготовка синтетического прокси требует предварительной сборки набора `Proxies.SelfTest`:

```powershell
dotnet build Tests/SelfTests/Proxies/Proxies.SelfTest.csproj -c Debug -p:Platform=x64
dotnet publish Presentation/OpenTgResearcherDesktop/OpenTgResearcherDesktop.csproj -c Release -r win-x64 --self-contained true -o Tests/SelfTests/bin/NetworkApp -p:Platform=x64 -p:WindowsPackageType=None -p:WindowsAppSDKSelfContained=true -p:AppxPackageSigningEnabled=false
./Tests/SelfTests/Test-DesktopNetwork.ps1 -ExecutablePath Tests/SelfTests/bin/NetworkApp/OpenTgResearcherDesktop.exe -Language Russian -Theme Dark
./Tests/SelfTests/Test-DesktopNetwork.ps1 -ExecutablePath Tests/SelfTests/bin/NetworkApp/OpenTgResearcherDesktop.exe -Language English -Theme Light
```

Скрипт проверяет пустую страницу, реальное TCP-подключение к loopback, компактную строку завершённой проверки в группе, сохранение раскрытия группы и очистку истории. Кнопка верхней панели перечитывает настоящий список прокси после добавления записи в тестовую БД. Проверяются положение обновления страницы непосредственно перед выбором языка, разные подписи кнопок обновления, недоступность прерывания и паузы без парсинга, доступность управления при ширине 800 и штатное закрытие с кодом 0 без исключений в журнале. Кадры 1200×1000 и 800×900 и журнал сохраняются в `Tests/SelfTests/bin/NetworkPage/<идентификатор>/`. Проценты, пауза, подтверждение, отмена и сохранение всех состояний в едином блоке активности проверяются автономно на настоящем сервисе, обработчике прогресса и исходной модели страницы; обработчик файлов после продолжения действительно записывает байты во временный каталог. Проверка не выполняет авторизацию, парсинг или скачивание через настоящий Telegram и не устанавливает пакеты Velopack.

## Скриншоты Desktop

Эталонный размер окна Desktop для скриншотов и записи заставки — **1200×1000 пикселей**. Снимайте всё окно, включая верхнюю панель, без последующего изменения размера изображения. Для комплекта используйте единые язык и тему; текущий комплект снят на русском языке в тёмной теме.

Сохраняйте PNG в `Assets/v<версия>/`, сохраняя назначения и имена снимков Desktop из `Assets/v0.8.200`. 
Обновляйте ссылки в [галерее](SCREENSHOTS.md), а запись текущей заставки — в `Assets/Animations/OpenTgResearcherDesktop_SplashScreen.gif`.

Используйте отдельные демонстрационные настройки и БД. 
Перед съёмкой скройте конфиденциальные данные переключателем верхней панели; для демонстрации содержимого чатов и контактов разрешено показывать только вымышленные данные. 
В кадр не должны попадать личные пути, телефоны, API ID / API hash, коды и пароли.

## Локализация при отладке Desktop

При запуске профиля `OpenTgResearcherDesktop (Package)` строки локализации читаются из `%LOCALAPPDATA%\Packages\<PackageFamilyName>\LocalState\Strings`.
До построения локализатора приложение автоматически создаёт папки `en-US` и `ru-RU` и копирует отсутствующие `Resources.resw` из ресурсов пакета.
При повторном запуске существующий файл заменяется, если его размер отличается от файла в пакете; файлы того же размера не перезаписываются.
`<PackageFamilyName>` зависит от идентификатора и издателя пакета.
Ошибки подготовки ресурсов записываются в журнал приложения.
При запуске профиля `OpenTgResearcherDesktop (Unpackaged)` используется каталог `Strings` рядом с исполняемым файлом.

### Проверка реального подключения

Для явной проверки реального подключения укажите БД и сохранённую сессию. Режим `--live` последовательно проверяет прямое соединение и первую запись с типом, отличным от `None`, в порядке списка страницы (сервер, тип, порт).
Проверка вызывает настоящий `TgConnectClientDesktop`, восстанавливает авторизацию, запрашивает текущего пользователя у Telegram и завершает клиент с проверкой сохранности и освобождения сессии. БД открывается только для чтения; для каждого подключения создаётся отдельная временная копия сессии, которая удаляется после проверки. Если нужен код или пароль, проверка останавливается.

```powershell
dotnet run --project Tests/SelfTests/Proxies/Proxies.SelfTest.csproj -- --live "...TgStorage.db" "$env:LOCALAPPDATA/OpenTgResearcherDesktop/current/OpenTgResearcher.session"
```

### Проверка чтения файла сессии

Расшифровку сессии можно проверить отдельно без сети: БД открывается только для чтения, временная копия проверяется штатным файловым хранилищем WTelegram, реквизиты не выводятся.
Успех этой проверки подтверждает чтение файла; действительность авторизации проверяется отдельным режимом `--live`.

```powershell
dotnet run --project Tests/SelfTests/ClientConnection/ClientConnection.SelfTest.csproj -p:Platform=x64 -- --inspect-session "...TgStorage.db" "...OpenTgResearcher.session"
```

## Проверка страницы чата

Селфтест проверяет исходные модели всех восьми страниц чата, обработчик выбора вкладок, разметку, сохранение и пагинацию на настоящих репозиториях с SQLite в памяти. Telegram заменён тестовым клиентом:

Проверки настроек включают сброс семи основных опций, сохранение остальных полей и общего черновика вкладок, автоматический сброс только при открытии чата без выбранных переключателей и сохранение до проверки подключения при запуске парсинга. При ошибке сохранения сеть не вызывается; если подключение недоступно, сохранённые изменения остаются в БД. «Пульт чата» объединяет настройки, скачивание и сведения в «Обзор». Отдельно проверяются восстановление живого прогресса и текущего файла при возврате к обзору, запрет повторного запуска, пауза и прерывание только выбранного чата, загрузка онлайн-сведений по запросу и переход к обсуждению и сетевой активности.

```powershell
dotnet run --project Tests/SelfTests/Chat/Chat.SelfTest.csproj -c Debug -p:Platform=x64
```

При проверке прерывания прогресс WTelegram обязан остановить передачу, а документ и фотография — получить состояние отмены без записи штатной отмены в журнал исключений. Команда страницы чата завершается без ошибки и перечитывает сохранённую позицию; отмена без запрошенного токена остаётся диагностируемой ошибкой. Эти сценарии проверяются автономно без подключения к Telegram и без чтения пользовательской сессии.

Для проверки настоящего окна закройте Desktop и укажите опубликованное unpackaged-приложение. Скрипт создаёт отдельные настройки, БД и путь сессии, открывает чат, последовательно посещает четыре основных раздела и обе вложенные вкладки содержимого, раскрывает сведения и дополнительные параметры обзора, проверяет журнал и код завершения:

В настоящем окне скрипт выключает семь основных переключателей, проверяет их включение кнопкой «Сброс настроек», сохранение обоих состояний автообновления и переход в сетевую активность. Параметры `-WindowWidth 1200 -WindowHeight 1000` задают эталонный размер окна, `-WindowWidth 800 -WindowHeight 900` — узкую разметку. `-Theme Light` и `-Theme Dark` задают оформление изолированного запуска. В узком окне скрипт прокручивает обзор к проверяемым элементам. Перед сохранением кадров проверяется, что окно Desktop находится на переднем плане.

```powershell
$desktop = '.../OpenTgResearcher/Releases/Desktop-x64/OpenTgResearcherDesktop.exe'
$chatTest = 'Tests/SelfTests/Chat/bin/Debug_x64/net10.0/Chat.SelfTest.dll'
./Tests/SelfTests/Test-DesktopChat.ps1 -ExecutablePath $desktop -SelfTestAssembly $chatTest -Language Russian -Theme Dark -WindowWidth 1200 -WindowHeight 1000
./Tests/SelfTests/Test-DesktopChat.ps1 -ExecutablePath $desktop -SelfTestAssembly $chatTest -Language English -Theme Light -WindowWidth 800 -WindowHeight 900
```

Без дополнительных параметров создаётся синтетический чат. Параметры `-SourceDatabase`, `-ChatId` и `-ChatDirectory` позволяют проверить выбранный чат из существующей БД:
источник открывается только для чтения, в тестовую БД копируются выбранный чат, до 100 последних сообщений и связанные пользователи. Реквизиты подключения и сессии не копируются.

Автономные проверки обновлённых вкладок выполняют выбор и очистку досье на настоящих репозиториях SQLite, расчёт итогов, долей и относительных полос, пустой и неверный период и сброс результата при изменении дат. Проверки обработчиков поиска отдельно вызывают исходные методы очистки и завершения обновления; настоящее выполнение команды поиска проверяется в окне Desktop. Скрипт проверяет ленту с обложкой, карточку профиля и смену выбранного участника в каталоге. Статистика в окне проверяется до расчёта: подключение к Telegram и получение настоящего списка участников не выполняются.

Проверки также воспроизводят возврат к ленте с незакрытым изображением, отображение названия чата для нулевого ID отправителя, автоматическую загрузку пустого каталога участников и расчёт отсутствующей статистики при активном подключении. Готовые участники и статистика того же чата сохраняются при повторном открытии. Сетевой расчёт проверяется тестовым клиентом; настоящий Telegram в этих проверках не используется.

Для диагностики пустого содержимого на полной БД используйте режим `--inspect-content`: база открывается только для чтения, исходная модель читает последнюю порцию и сверяет её с сообщениями выбранного чата. При успехе в вывод попадают только ID чата и количество сообщений. Замените пример ID на нужный чат:

```powershell
$chatId = 123456789
dotnet run --project Tests/SelfTests/Chat/Chat.SelfTest.csproj -c Debug -p:Platform=x64 -- --inspect-content "../TgStorage/TgStorage.db" $chatId
```

Результаты сохраняются в `Tests/SelfTests/bin/ChatPage`. Скрипт проверяет открытие и навигацию без Telegram, сохранение обоих состояний автообновления через диалог и перечитывание SQLite.
При выборе существующей БД также проверяется получение авторов сообщений в каталог участников; изменяется только тестовая выборка. Настройки должны показывать выбранный чат уже при первом открытии.
Параметр `-CheckMediaPreview` проверяет синтетический чат с настоящей JPEG-обложкой: находит видимый элемент `Image`, проверяет отрисованный цвет и сохраняет снимок области обложки. Этот режим запускается без `-SourceDatabase`.
Дополнительно выполняются настоящие нажатия по изображению и фону увеличенного просмотра; переход к профилю с открытым просмотром и возврат должны показать непустую ленту без пустой панели поверх сообщений. Каталог синтетических участников проверяется сразу после открытия, без нажатия «Загрузить ещё».
Он также проверяет скрытие обложки переключателем конфиденциальных данных и отображение подсказки пустого списка после подтверждённой очистки тестовой выборки.
Реестр чатов проверяется с пятью локализованными заголовками; при доступной ширине страницы меньше 900 колонка времени обновления скрывается, остаются четыре заголовка. Скрипт проверяет поиск без результатов, возврат списка, фильтр «В работе», сортировку, раскрытие сведений, конфиденциальность, ширину поиска, границы кнопок и открытие выбранного чата. Снимки сохраняются рядом с журналом.
Автономные селфтесты реестра удерживают настоящие SQL-запросы репозиториев парсера и одновременно открывают список, пульт, ленту, участников, профиль и статистику через независимые контексты SQLite. Отдельно проверяются фактические количества сообщений и медиа, фильтр работающих чатов до пагинации, пауза выбранной операции и сохранение цели парсинга при просмотре другого чата. Передача данных Telegram в этих тестах подменяется; проверка с настоящим подключением остаётся в пользовательском контуре.
Во время парсинга статистика читается по сохранённым авторам и сообщениям; параллельное обновление справочника пользователей через Telegram не выполняется. Локальный просмотр профиля не использует сетевой токен парсера.
Кнопка «Открыть чат» в реестре выполняет прямой переход без диалога. Кнопка «Парсинг / Прервать» расположена слева от паузы: запуск читает сохранённые настройки выбранного чата в отдельный снимок, остановка подтверждается и относится только к выбранному чату. Другой чат можно запустить до завершения текущего через реестр или его пульт. Повторный запуск того же чата блокируется в интерфейсе и ядре до завершения его задач. Просмотр списка и открытие чатов остаются доступными.

Каждый парсинг владеет снимком настроек и фильтров, кешем, буферами и отдельными репозиториями. Контекст запуска передаётся дочерним задачам через `AsyncLocal`; завершение освобождает только ресурсы своего чата. Подключение Telegram остаётся общим, запросы и передачи разных чатов могут перекрываться. Защитная пауза `FLOOD_WAIT` учитывается всеми новыми запросами; отмена одного чата не снимает ограничение Telegram для остальных. Количество потоков применяется к каждому чату отдельно. Пауза и прерывание в пульте и реестре относятся к выбранному чату; общая остановка приложения отменяет все запуски.

Редактирование в пульте блокируется только на время парсинга открытого чата, включая паузу и ожидание остановки. Другой чат можно редактировать, сохранять и сбрасывать независимо от общей сетевой активности. Сохранение использует отдельный репозиторий. Селфтесты `ChatEditingUsesSelectedParsingState` и `ChatEditsPersistWhileOtherChatParses` проверяют привязки полей и действий, блокировку работающего чата до завершения, разблокировку после остановки и запись настроек другого чата при занятом контексте общего хранилища.

Селфтесты `ParallelParsing*`, `ParallelTelegramCallsOverlap`, `ParallelFloodWaitSurvivesOneCancellation`, `ParallelDashboardKeepsSelectedChat` и `RegistryStartsTwoChats` проверяют перекрывающиеся запуски, повторный запуск после отмены, защиту от дублирования одного чата, независимые каталоги и сообщения с одинаковыми ID, паузу и прерывание, общую остановку, сохранение черновика при навигации и общую защитную паузу. Настоящий цикл парсинга обрабатывает подготовленные ответы Telegram и записывает сообщения в отдельную SQLite в памяти, а файлы — во временные каталоги. Сетевой транспорт в этих проверках подменяется; одновременный парсинг с настоящим подключением проверяется пользователем.
Селфтесты чата также проверяют медиафайлы в отдельных временных каталогах: настоящий обработчик выбирает файл и открывает поток, подменяется только передача байтов из Telegram.

Для ограниченной сетевой проверки готовых документов используется отдельная команда:

```powershell
dotnet $chatTest --live-media '.../TgStorage.db' '.../OpenTgResearcher.session' ID '.../dir'
```

Проверка восстанавливает существующую авторизацию из временной копии сессии, читает метаданные двадцати документов и дважды вызывает настоящий обработчик пропуска готовых файлов.
Исходная БД открывается только для чтения, готовые файлы блокируются от записи, скачивание запрещено. Новые коды и пароли не запрашиваются; временная сессия удаляется после отключения.
Этот режим проверяет пропуск существующих документов; полный парсинг архива и восстановление отсутствующих файлов он не запускает.

Для ограниченной проверки парсинга и настоящей передачи файлов используется отдельный режим:

```powershell
dotnet $chatTest --live-chat '.../TgStorage.db' '.../OpenTgResearcher.session' ID
```

Он читает каталог выбранного чата из БД, восстанавливает авторизацию из копии сессии и разбирает последние несколько сообщений в отдельную SQLite в памяти.
Затем закрывает TCP только тестового клиента, проверяет восстановление авторизованного запроса и повторный разбор без дубликатов.
Из последних ста сообщений выбираются до двух документов размером до 1 МиБ, скачиваются в созданный тестом подкаталог каталога чата и проверяются по размеру.
После отключения тест удаляет только этот подкаталог и копию сессии. Исходные БД, сессия и готовые файлы не изменяются; полный архив не обрабатывается.
Если авторизация недействительна, каталог недоступен или подходящих документов нет, проверка завершается с ошибкой и сохраняет журнал.

## Проверка страницы обновлений Desktop

Пользовательское описание верхней панели и обновлений: [README](README.md#верхняя-панель-и-обновление-desktop).

Селфтесты используют исходные VM и службу навигации, настоящие ресурсы обоих языков и подменённый источник пакетов:

```powershell
dotnet run --project Tests/SelfTests/Updates/Updates.SelfTest.csproj -c Debug -p:Platform=x64
```

Проверка опубликованного окна использует отдельные настройки и тестовую БД, проверяет подпись настроек, переход на страницу, подтверждения и доступность журнала:

```powershell
./Tests/SelfTests/Test-DesktopUpdates.ps1 -ExecutablePath '.../OpenTgResearcherDesktop.exe' -Language Russian
./Tests/SelfTests/Test-DesktopUpdates.ps1 -ExecutablePath '.../OpenTgResearcherDesktop.exe' -Language English
```

Параметр `-Toolbar` дополнительно проверяет элементы верхней панели настоящими нажатиями мыши, переключение языка и темы, сохранение выбора и геометрию при ширине окна 800 и 1280. Для конфиденциальных данных проверяются оба состояния, скрытие поля пути тестовой БД в настройках и сохранение состояния при переходах между страницами без подключения Telegram.
Проверка сетевого сканирования использует отдельную БД и TCP-сервер loopback с заполненной очередью подключений. Она сравнивает кадры верхнего логотипа до, во время и после проверки прокси, проверяет значок настоящего окна и штатное завершение. Перед запуском соберите `Tests/SelfTests/Proxies/Proxies.SelfTest.csproj` в Debug x64 и закройте Desktop:

```powershell
./Tests/SelfTests/Test-DesktopProxies.ps1 -ExecutablePath '.../OpenTgResearcherDesktop.exe' -Language Russian -NetworkLogo -Theme Dark
./Tests/SelfTests/Test-DesktopProxies.ps1 -ExecutablePath '.../OpenTgResearcherDesktop.exe' -Language English -NetworkLogo -Theme Light
```

Параметр `-Splash` проверяет последовательность эффектов и кадры настоящего окна, движение точки со шлейфом снаружи кнопки «Продолжить», обычное нажатие кнопки, общий знак OTR в верхней панели при ширине 800 и 1280 и штатное закрытие. Параметр `-Theme Light` или `-Theme Dark` задаёт тему тестового запуска. Мягкое появление и орбита выполняются параллельно пять секунд, затем сканирование делает один проход. Инициализация идёт параллельно; после неё и вводных пяти секунд становится доступна кнопка «Продолжить». Мягкая точка с коротким затухающим шлейфом обходит кнопку по часовой стрелке до ухода со заставки. При отключении анимаций Windows содержимое видно сразу и дополнительного ожидания нет.

```powershell
./Tests/SelfTests/Test-DesktopUpdates.ps1 -ExecutablePath '.../OpenTgResearcherDesktop.exe' -Language Russian -Splash -Theme Dark
./Tests/SelfTests/Test-DesktopUpdates.ps1 -ExecutablePath '.../OpenTgResearcherDesktop.exe' -Language English -Splash -Theme Light
```

Эти проверки не устанавливают новую версию и не подтверждают обновление установленного приложения через GitHub; полный переход между выпусками проверяется отдельно в пользовательском контуре.

## Проверка запуска Velopack

Desktop и Console вызывают `VelopackApp.Run()` в начале синхронного `Main`, до создания интерфейса, сервисов и хранилища.
Приветствие после первой установки выводится после подготовки приложения. Селфтест читает IL готовых сборок без их запуска: проверяет порядок вызовов, отсутствие повторного запуска Velopack, STA и запуск WinUI в Desktop.
После сборки решения `Debug | x64` выполните из корня решения:

```powershell
$desktopAssembly = 'Presentation/OpenTgResearcherDesktop/bin/Debug_x64/net10.0-windows10.0.19041.0/win-x64/OpenTgResearcherDesktop.dll'
$consoleAssembly = 'Presentation/OpenTgResearcherConsole/bin/Debug_x64/net10.0/OpenTgResearcherConsole.dll'
dotnet run --project Tests/SelfTests/DesktopStartup/DesktopStartup.SelfTest.csproj -p:Platform=x64 --no-build -- --velopack $desktopAssembly $consoleAssembly
```

При упаковке `vpk` должен подтвердить `Verified VelopackApp.Run()` в `Program::Main()` для каждого приложения. Проверка IL и упаковка не заменяют проверку установки и обновления пользователем.

Для проверки опубликованного Desktop без MSIX выполните в PowerShell из корня решения:

```powershell
./Tests/SelfTests/Test-DesktopReleaseStartup.ps1 -ExecutablePath '.../OpenTgResearcher/Releases/Desktop-x64/OpenTgResearcherDesktop.exe' -Language Russian
./Tests/SelfTests/Test-DesktopReleaseStartup.ps1 -ExecutablePath '.../OpenTgResearcher/Releases/Desktop-x64/OpenTgResearcherDesktop.exe' -Language English
```

Перед проверкой закройте Desktop. Каждый запуск использует отдельные настройки, БД и путь сессии в `Tests/SelfTests/bin/ReleaseStartup`; подключения к Telegram нет.
Проверка требует сохранения языка после загрузки заставки, продолжения работы процесса и штатного закрытия с кодом 0. Она воспроизводит вылет UWP `ResourceContext` в Release без MSIX, который не обнаруживается одной сборкой и упаковкой.

## Проверка закрытия Desktop

Порядок завершения приложения: [README](README.md#закрытие-desktop).

Для воспроизведения сценария «главная страница → закрытие» в открытой Visual Studio выберите это решение, конфигурацию `Debug | x64` и профиль `OpenTgResearcherDesktop (Package)`. Остановите текущую отладку, затем выполните в PowerShell 7:

```powershell
./Tests/SelfTests/Test-DesktopShutdownVs.ps1 -CloseDelaySeconds 3
```

Селфтест запускает выбранный профиль, нажимает «Продолжить», подтверждает загрузку главной страницы по новым строкам журнала и закрывает окно. Успех требует завершения процесса с кодом 0. При остановке отладчика состояние сохраняется в `Tests/SelfTests/bin/DesktopShutdownVs/break.txt`; неудачный запуск остаётся доступен для диагностики. SHA256 загруженной WinUI выводится в консоль; параметр `-ExpectedXamlSha256` позволяет проверить конкретную DLL. Команда с `-StopFailedRun` завершает активную отладку этого решения.
Отдельная проверка под CDB из Windows SDK не включает инструменты Live Visual Tree. Каталог Windows SDK определяется через системный каталог Program Files (x86); другой путь можно передать параметром `-DebuggerPath`, в том числе относительно текущего каталога консоли:

```powershell
./Tests/SelfTests/Test-DesktopShutdown.ps1 -PackageFullName '<PackageFullName>' -ReadyPattern 'Notification loading|Загрузка уведомлений' -OpenMainPage -CaptureManagedExceptions
```

В дампе одного из сбоев под VS обнаружен стек `RuntimeObject.GetXamlRoot → RemoveRootObjectFromLVT → XamlIsland.Close`; аналогичный сбой описан в [отчёте Microsoft](https://github.com/microsoft/microsoft-ui-xaml/issues/10587). Прохождение CDB не подтверждает устранение этой ошибки под VS. Повторная проверка под VS пока нестабильна; подтверждённого исправления нет.
